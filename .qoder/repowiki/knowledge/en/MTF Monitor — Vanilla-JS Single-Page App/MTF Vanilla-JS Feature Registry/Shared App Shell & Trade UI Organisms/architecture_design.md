Each file is a self-contained IIFE that lazily resolves helpers from `global.MTFComponents` and `global.MTFAppHelpers`, then publishes its public API via `global.MTFRegister(...)`. Internal layering follows an organism/molecule split: `app-shell.js` provides the chrome — BottomBar (O5), Sheet/CupertinoPane wrapper (O22), AppDialog/Bootstrap Modal + `confirmAction` (O23), and AppHeader (O3); `trade-list.js` composes molecules (P&L, leverage, detail rows, actions) into list-item and grouped-list organisms; `trade-sheets.js` implements per-trade edit/view sheets (view, charges, interest, target sell, buy price, leverage, hold dates) as reusable molecules (`renderTradeDetailsList`, `buildTradeMetaTags`, `chargesTable`, etc.); `trade-modal.js` orchestrates the add/edit transaction sheet with form state and preview calculations; `search-page.js` renders filtered trade lists driven by `MTFAppHelpers.tradePages`; `router.js` wires Page.js routes to `global.renderAppPage` behind a `withLoading` middleware. Dependency direction is one-way: this module depends only on `MTFComponents` (rendering primitives, toast, date helpers) and `MTFAppHelpers` (data accessors like `getTransaction`, `calculateTrade`, `refreshTradeListViews`) — it never imports sibling features, keeping it truly cross-feature.
