Three sibling sub-packages share a global-namespace registration pattern so they can be loaded as plain `<script>` tags in any order:

- `shared/db/` — data plane. `_registry.js` exposes `MTFDbRegister(exports)` which merges exports onto both `window.MTFDb` and `globalThis`, optionally wrapping each method via `MTFLogger.trace`. `firebase-config.js` registers `FIREBASE_CONFIG` / `DEFAULT_SYNC_CODE`; `auth-service.js` publishes `MTFAuth` (Google sign-in, uid, onAuthStateChanged); `local-db.js` is currently a stub (feature removed by user request); `BaseRepository.js` is an abstract class exposing `getOwnerUid()` (uid or legacy syncCode) and `getDb()` (Firebase Firestore instance). The core `db-service.js` initializes Firebase conditionally (`isFirebaseConfigured()` checks for placeholder keys), manages a `syncCode` + `syncStatus` lifecycle, pushes transactions/watchlist to standalone Firestore collections (`transactions`, `watchlist`, `closed_trades`) while stripping them from the main document, and provides generic CRUD (`createDocument`/`getDocument`/`updateDocument`/`deleteDocument`/`getCollection`/`listenToCollection`/`listenToDocument`/`batchWrite`) plus a `parseQueryConfig` DSL (`where`/`range`/`arrayContains`/`filters`).
- `shared/lib/` — UI/runtime helpers. `_registry.js` exposes `MTFRegister(exports)` which merges onto `window.MTFComponents`; every atom file wraps its code in an IIFE and calls `MTFRegister({...})`. `bootstrap.js` contains many such atoms (Modal/Toast wrappers, loading indicator, date-field chip, button, badge, label, icon-button, empty-state, search bar, dropdowns, form field group, money value block). `format.js` provides INR formatting, amount-in-words, render/paint pairs for amounts/cards/chips, and collapse helpers. `activity-log.js` installs `MTFLogger` with feature-tagging and per-feature toggles read from `AppPermissions`/`localStorage`. `broker-logos.js` maps broker names to inline base64 SVG/PNG assets.
- `shared/css/` — design tokens. `colors.css` defines `--gr-*` brand variables; `_variables.css` bridges them to Bootstrap 5 tokens (`--bs-primary`, `--bs-body-bg`, etc.) and ships all page-level layout rules (sheet panes, modal z-indexing, bottom-bar clearance).

Dependency direction is one-way: `db-service.js` depends on `MTFDb`/`MTFLocalDB`/`MTFAuth`/`MTFLogger` being present at call time but never imports them; `auth-service.js` calls back into `MTFDb.refreshAllViews`/`clearAllCaches` through the registry. There is no build manifest — files are consumed directly by the host HTML.
