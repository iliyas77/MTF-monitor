Each feature under `features/<name>/` is an IIFE that registers its page renderer via `global.MTFRegister({ renderXxxPage })`. The shared `features/common/app-shell.js` owns the bottom navigation (`BOTTOM_BAR_ITEMS` maps ids like `trades|market|gold|calendar|more` to labels/icons), the Cupertino Pane-based `Sheet` host, the Bootstrap-backed `AppDialog`, and the header router; it calls each feature's `renderXxxPage` when the nav item is tapped. Features communicate indirectly: `calendar-page.js` reads closed trades from `global.MTFAppHelpers.tradePages.getTransactions()`, while every feature resolves UI primitives (icons, date pickers, toast, trade list rendering) from `global.MTFComponents` rather than importing one another. Data persistence is per-feature — `positions/`, `watchlist/`, and `more/` own their own Firestore + localStorage repositories; `calendar/` and `gold/` are read-only consumers of those stores or external APIs. The sibling `components/` directory provides pure HTML fragment builders (card, grid, metrics-cell) used by both server-rendered templates and these client features.
