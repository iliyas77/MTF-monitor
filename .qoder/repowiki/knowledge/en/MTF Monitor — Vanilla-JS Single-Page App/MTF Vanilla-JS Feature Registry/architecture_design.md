Each feature under `features/<name>/` is an IIFE that calls `global.MTFRegister({ renderXxxPage })` to publish its page renderer; `features/common/app-shell.js` owns the bottom navigation (`BOTTOM_BAR_ITEMS` maps ids like `trades|market|gold|calendar|more`), the Cupertino Pane-based `Sheet` host, the Bootstrap-backed `AppDialog`, and the header router, invoking the registered `renderXxxPage` when a nav item is tapped. Features stay decoupled by resolving cross-feature UI primitives from `global.MTFComponents` at call time with optional-chaining fallbacks, and share data indirectly through `global.MTFAppHelpers` (e.g. `calendar-page.js` reads closed trades via `tradePages.getTransactions()`). Data persistence is per-feature — `positions/`, `watchlist/`, and `more/` own their own Firestore + localStorage repositories; `calendar/` and `gold/` are read-only consumers of those stores or external APIs. The sibling `components/` directory provides pure HTML fragment builders (card, grid, metrics-cell) consumed by both server-rendered templates and these client features.
